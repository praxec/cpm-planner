# P4 — Analysis Tools: lint, resource schedule, scorecard, Monte Carlo, simulate (#20, #19, #23a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Before (or without) submitting, a planner can lint a graph, level it against real resource capacities, score it (risk, complexity, parallelism, Monte Carlo P50/P80/P95), and simulate what-ifs — all read-only — and cohorts dispatch in levelled order.

**Architecture:** Pure, read-only analysis modules over `PlanGraph` (+ the CPM result from `schedule::compute_cpm`): `src/lint.rs`, `src/resource_schedule.rs`, `src/metrics.rs`, `src/monte_carlo.rs`, composed by `src/simulate.rs`. Each is exposed as a `plan.*` tool that accepts an inline `graph` or a stored `plan_id` (file `path` arrives in P4P). Nothing here mutates state. Synthetic `__start__`/`__finish__` tasks are excluded from every metric and every per-deliverable output row.

**Tech Stack:** Rust 1.99.0, serde, rmcp; new deps `rand = "0.9"`, `rand_distr = "0.5"`, `rand_chacha = "0.9"` (seeded, reproducible Monte Carlo; `default-features` minimal where possible).

**Spec:** `docs/superpowers/plans/2026-10-09-backlog-roadmap.md` § P4 (incl. the Monte Carlo decision) + issues #20, #19 (with its CCPM-buffer comment), #23 (part a).

## Global Constraints

- All new tools are **read-only**: no store writes, no audit events, no lock changes.
- Every new tool: constant + `PLAN_TOOL_NAMES` + schema in `plan_tool_definitions` + `instructions()` text + README tool table + `tests/server_integration.rs` roundtrip. Tool count text ("N tools") updated everywhere it appears.
- Tool inputs: exactly one of `graph` (inline `PlanGraph`) or `plan_id`; both or neither → invalid-params error. Arg structs `deny_unknown_fields`.
- Synthetic endpoints (`START_ID`, `FINISH_ID`) never appear in per-deliverable rows of lint/schedule/scorecard/Monte Carlo output and never count in metrics.
- Scheduled length of a deliverable = `duration_hours`, else `estimated_effort_hours`, else (new) `estimate.likely`, else zero for milestones, else the estimator — one helper (`schedule::scheduled_length`) used everywhere; lag from prerequisite edges applies in every scheduler here.
- Determinism: same input (and same `seed`) → byte-identical JSON output. Ties broken by id.
- New `Deliverable` fields go into `hash_graph`. Adding `estimate` does not change kernel output for existing graphs (no stored graph has it), so `CPM_VERSION` stays 3.
- Error-code prefixes unchanged; new analysis-input errors use `INVALID_GRAPH:` (graph problems) or a new `INVALID_CAPACITIES:` prefix (schedule capacities).
- CHANGELOG `[Unreleased]` (single Added/Changed headings), README, `instructions()` updated per task.
- CRLF files (`src/plan.rs`, `src/planner.rs`, `src/ports.rs`, `src/locks.rs`, `src/task.rs`, `tests/algorithm.rs`) keep CRLF; new files are LF. No whole-file churn.
- `cargo fmt --all --check`, `cargo test`, `cargo clippy --all-targets -- -D warnings` green on 1.99.0.

## Review Focus

1. **A cyclic graph** passed to `plan.lint` returns a `CYCLE` finding naming the actual loop (not an error), and to `plan.simulate` returns `INVALID_GRAPH` (Tasks 1, 6).
2. **A resource with no capacity entry** → `INVALID_CAPACITIES:` naming every missing resource (Task 2).
3. **Capacity 1 for everything** turns the resource schedule into a serial chain whose makespan equals the sum of scheduled lengths (Task 2).
4. **A graph with no `estimate` anywhere** → Monte Carlo P50 = P80 = P95 = the CPM makespan and every criticality index ∈ {0, 1} (Task 5).
5. **Same seed twice** → identical Monte Carlo output; different seeds → different samples but same shape (Task 5).

**Interfaces:**

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum Severity { Error, Warning, Info }

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct LintFinding {
    pub code: String,          // stable codes below
    pub severity: Severity,
    pub message: String,
    pub ids: Vec<String>,      // deliverables involved (loop order for CYCLE)
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub path: Option<String>,  // file path for file findings
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct LintReport { pub clean: bool, pub findings: Vec<LintFinding> }

pub fn lint(graph: &PlanGraph) -> LintReport;
```
  Codes (severity): `DUPLICATE_ID` (error), `RESERVED_ID` (error), `UNKNOWN_PREREQUISITE` (error), `CYCLE` (error; `ids` = the loop in order, first id repeated at end, e.g. `["a","b","c","a"]`; one finding per distinct cycle found by DFS), `UNORDERED_FILE_OVERLAP` (error; exclusive involved, same rule as submit), `INVALID_VALUE` (error; negative/non-finite effort, duration, lag), `REDUNDANT_EDGE` (warning; `d ← u` when u is an ancestor of another prerequisite of d), `NO_RATIONALE` (warning; edge without `consumes`, also accepting legacy `metadata.consumes[<prereq id>]` string), `INTERFACE_EDGE_NOT_CONTRACT` (warning; `kind: interface` edge whose target lacks `metadata.contract == true`), `NO_MILESTONE` (info; graph has no milestone), `FEEDS_NO_MILESTONE` (warning; a deliverable that is neither a milestone nor an ancestor of one — only when ≥1 milestone exists), `NO_ARTIFACT` (info; `metadata.artifact` missing). `clean` = no error or warning findings. Findings sorted by (severity, code, ids). Lint never panics on bad graphs; graph-structure findings that depend on acyclicity (REDUNDANT_EDGE, FEEDS_NO_MILESTONE) are skipped when a CYCLE or UNKNOWN_PREREQUISITE exists.
  Tool `plan.lint { graph | plan_id }` → `LintReport` JSON.

**Interfaces:**

```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct ScheduleRequest {
    pub capacities: std::collections::BTreeMap<String, u32>,
    #[serde(default = "default_resource_key")] pub resource_key: String, // "owner" → metadata.owner
    #[serde(default = "default_buffer_pct")] pub project_buffer_pct: f32, // 25.0
}
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct ScheduledRow { pub id: String, pub resource: String, pub start: f32, pub finish: f32 }
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct ResourceLoad { pub resource: String, pub capacity: u32, pub busy_hours: f32, pub utilisation: f32 }
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum WaitKind { Start, Dependency, Resource }
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct ChainLink { pub id: String, pub waited_on: WaitKind }
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct FeedingBuffer { pub joins: String, pub from_chain: Vec<String>, pub buffer_hours: f32 }
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct ResourceSchedule {
    pub makespan: f32,
    pub cpm_makespan: f32,             // unconstrained, for comparison
    pub rows: Vec<ScheduledRow>,       // graph order, no synthetic rows
    pub load: Vec<ResourceLoad>,       // sorted by resource
    pub driving_chain: Vec<ChainLink>, // execution order, first link waited_on Start
    pub project_buffer_hours: f32,     // pct × sum of scheduled lengths on driving_chain
    pub feeding_buffers: Vec<FeedingBuffer>,
}
pub fn resource_schedule(graph: &PlanGraph, req: &ScheduleRequest) -> Result<ResourceSchedule, PlannerError>;
```
  Algorithm: event-driven list scheduling (no fixed time step). Priority among ready deliverables = longest remaining tail (scheduled length + max over successors of (lag + tail)), ties by id. A deliverable is ready at `max(finish(pred) + lag)`; it starts when ready and a unit of its resource is free (earliest-free unit, ties by unit index). Resource of a deliverable = `metadata[resource_key]` as string, else `"unassigned"`. Every resource used must be in `capacities` with count ≥ 1, else `PlannerError::InvalidCapacities { missing: Vec<String> }` with message `"INVALID_CAPACITIES: no capacity for resources [a, b]"` (also for count 0). Zero-length deliverables (milestones) consume no resource time but still respect dependencies. Driving chain: walk back from the latest finisher; at each step prefer a dependency predecessor whose `finish + lag == start` (`Dependency`), else a same-resource deliverable whose `finish == start` (`Resource`), ties by id; stop at start 0 (`Start`). Feeding buffers: for each non-driving deliverable that is a direct prerequisite of a driving-chain deliverable, `from_chain` = the longest dependency chain ending at it (ids, execution order) and `buffer_hours = pct × sum of its scheduled lengths`; sorted by `joins` then first id.
  Tool `plan.schedule { graph | plan_id, capacities, resource_key?, project_buffer_pct? }` → `ResourceSchedule` JSON.

// src/monte_carlo.rs
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct MonteCarloRequest {
    #[serde(default = "default_iterations")] pub iterations: u32, // 2000, max 50_000
    #[serde(default = "default_seed")] pub seed: u64,             // 0xC0FFEE
}
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct CriticalityIndex { pub id: String, pub index: f32 }   // share of runs critical
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]

    pub p50: f32, pub p80: f32, pub p95: f32, pub mean: f32,
    pub deterministic_makespan: f32,
    pub criticality: Vec<CriticalityIndex>,   // graph order, no synthetic

Percentiles: nearest-rank on sorted makespans. `iterations` > 50 000 or 0 → `INVALID_GRAPH: iterations must be between 1 and 50000` (reuse InvalidGraph). Correlation of a constant series = 0.
